## Documentation and scope

Before planning or changing this source repository, use one validated checkout of the authoritative `Geurtsy/GeurtsGameForge_Commandments` repository. Read its `AI_READ_FIRST.md`, then its sibling `GeurtsTechniqueManifest.md` and every technique selected for the task in ForgeDevelopment mode. Record that documentation commit and keep selected files from that same commit. Use an existing validated local source checkout when available; report an unavailable documentation prerequisite before changing source.

This is a package source repository. Keep source publication and installation into a Unity consumer separate, following the manifest-selected owners.

## Required delivery to remote main

After completing and validating each authorized update, commit the scoped changes and push or merge them into this repository's remote `main` branch. The user has given standing authorization for the ordinary commits, pushes and merges needed for this delivery; do not ask for the same approval again.

Follow the repository's required checks, pull-request workflow and branch protections, and preserve unrelated work. Verify the intended commit is present on remote `main` before reporting delivery complete. A local commit, local main branch, candidate branch or open pull request is an intermediate step. If delivery is blocked, report the exact blocker and remaining step.

The shared Automation Technique's delivery rule applies independently to every Geurts Game Forge package source repository, including God, BigBang and the passive Commandments compatibility adapter, and to `Geurtsy/GeurtsGameForge_Commandments` itself. Deliver each owning repository changed by a task; pushing a Unity test project does not deliver those sources. Apply the documentation's versioning and publish-before-consumer-installation requirements for affected releases.
